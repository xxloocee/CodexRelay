# CodexRelay v2.3.10

本次更新修复 Codex 配置切换受旧配置和历史备份阻塞的问题，改为备份当前文件后直接写入目标请求通道。

## 修复与调整

- 旧备份缺失、哈希不符、旧本地令牌或配置归属不一致不再阻止 Codex 切换；令牌更新直接写入。主界面、托盘、二狗子令牌与故障切换采用同一写入规则。
- 切回官方固定选择原生 OpenAI，不再误恢复成第三方 Provider；可找回备份中的 OAuth 登录或 keyring/auto 登录来源，避免陈旧 OAuth 文件改变钥匙串认证来源。找不到登录信息时仍写入官方通道，由 Codex 提示登录。
- 写入前将现有 config.toml 和 auth.json 按原 Provider 标名备份到 CodexRelay 数据目录的 client-backups/codex/；坏 TOML 保存原字节后重建。
- 保留 Windows 沙箱、MCP、插件、项目、未使用的 Provider 和未启用的配置档。只调整当前请求通道；未指定默认模型时保留用户模型。
- 请求通道及认证一致时不重复写入或备份；仅令牌变化时保留原 TOML 字节。需要重写 TOML 时不保留注释和原排版。
- 开启“跳过配置文件替换”时只切换 Relay 上游。历史会话修复保持独立，不再成为配置切换前置条件。
- 修复 Windows 文件权限差异造成的回退误判，并保留其他客户端在不重复写入时的并发修改检查。

## 使用说明与验证范围

切换成功表示本地配置写入与 Relay 路由保存完成，不代表上游令牌、网络或客户端重新加载已验证。强制写入可能覆盖同时发生的外部编辑；真实文件读取、备份或写入失败仍会明确提示。需要时重新打开 Codex；历史列表异常可使用独立的“修复历史会话”。

本次定向后端测试、合成配置验收及两轮独立审查通过。未修改真实用户配置，未进行真实 Codex 登录、系统钥匙串或各平台实机验证；各平台构建结果以本版本 Actions 为准。Windows 支持应用内更新；macOS/Linux 使用安装包更新，不提供应用内开机自启动配置。Linux 需提供 libwebkitgtk-6.0；安装包未签名/公证。
